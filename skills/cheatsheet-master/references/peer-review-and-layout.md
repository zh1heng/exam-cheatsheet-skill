# 按题型代表题验收、反馈迭代与排版

## 默认：全量分类，代表题实际作答

先交付可用 v1 初稿，标出待验收项。最终默认做题型代表题验收；只有用户明确要求全量逐题验收，才进入 [acceptance-harness.md](acceptance-harness.md) 的严格模式。完整分类不意味着每题都要写答案，也不意味着每题已经通过。

1. **建立分类表。** 从用户指定范围和现有来源登记原题ID、页码及所属题型；同题多份副本保留别名。不复制整份题干、答案或逐题rubric到分类表。缺图、来源不明、不能确定所属类别的题单列未决，不能强行并入已覆盖类别。
2. **按解题差异分族。** 分类键是“方法＋会改变解法的前提/边界＋要求的输出”，而非宽泛章节名。同样流程仅换数值、人名或背景的题共用代表；会改变算法、控制流、有效条件、证明义务、输出形式或模板组合的题另列子类。来源年份不同本身不构成新类。
3. **选最小充分代表集。** 每族选一道能体现主要推理和输出的原题，优先老师强调、正式卷且要求充分的题，不只挑最容易的。已有代表未覆盖的重要条件/边界/迁移问法才增补题目，优先用尚未看答案的现有原题；没有合适原题时才生成并标明变式。不按每条小抄机械添加两道新题。开始前简报总题数、分类数、代表题数及选择理由；普通选题不另设审批关卡。
4. **独立作答与分开复核。** 默认一个额外解题 agent 分批只做选定题，主制作 agent 复核；需要分片时各 agent 的题集互斥，不另派全题复查团队。只提供原题、必要题图及候选小抄/实际渲染，不提供作者路线或答案。解题者记录首选区域、实际条目、完整答案或失败、外部补充知识。复核者对照官方答案或标注的独立推导，检查完整答案正确、必要答案要点加权支持≥90%、关键步骤均受支持。评分要点在检查表现前固定，可复用适用的同族rubric；无需为未选题生成评分账本。
5. **修复与增量复测。** 改动影响的代表题、失败题以及共享模板依赖必须复测；新发现的实质差异可拆族并补代表，不自动展开整个题库。未改内容复用已有证据，记录旧版本和保留依据；无法确认影响边界则扩大相关族检查。只改字号、颜色、栏位，检查实际最终渲染和受影响定位，不重做内容答案。用户要求仅排版或不验收时，服从该范围。

分类表示例：

| 族/子类 | 方法与关键区别 | 全部成员ID/题源 | 选中代表及理由 | 必要附加变式 | 状态/未决 |
|---|---|---|---|---|---|
| 线性查找 | 返回首个匹配下标，无匹配为-1 | 原题ID列表 | 含命中与未命中要求的一题 | 空数组规则未覆盖时补一题 | 其余同类仅分类，未逐题解答 |
| 逆序副本 | 新数组，输入不变 | 原题ID列表 | 要求new array的一题 | 视已有覆盖补充 | 与原地逆序分开 |
| 原地逆序 | 修改原数组、成对交换 | 原题ID列表 | 要求in place的一题 | 视已有覆盖补充 | 不用副本题替代 |

选题冻结后按选定ID核对已做/未做，报告不同层次的数量：原题总数、分类数、选定原题数、必要变式数、实际作答数、通过数、只分类未测数、来源未决数。不能把代表题通过率当成原题总题库通过率，也不能把原题所属族已验证说成原题已经作答。

## 简明证据与停止条件

每个实测题保留：题源与ID、候选版本、实际解题者、完整答案或失败、实际入口/模板组合、独立复核依据、必要要点的支持比例与关键缺口。模型凭自身知识补出的算法/API/条件必须单列，不计小抄支持。默认可用紧凑 Markdown 表及答卷引用，不强制全量 JSON 账本或运行旧版脚本。

状态区分：实测通过、实测未通过、仅分类未测、来源未决。没有学生实测不报告学生检索速度或掌握率；没有实物打印不宣称已验证打印体验。

> 独立解题任务：只对附带的代表题ID实际作答，不扩展到分类表的其他成员。使用候选小抄及必要题图，不看答案和作者路线。每题返回实际查找入口、完整步骤及答案、外部补充知识；不会则记录失败。不要修改小抄，不主动增加题目或代理。

默认一轮代表集初验，发现问题后最多两轮定向修复复测；无新失败不重复验收。用户预算优先，无法测量token时不得声称已控制到精确token上限，可采用明确的题数/轮数上限。达到限制时交付可用版本、已完成范围与剩余问题，不为获得通过标签继续全量重做。

通过结论必须写成“题型代表题验收通过”，列出实测范围与限制。条件：选定代表及必要变式完整作答且通过正确性、90%支持、关键项与定位检查；未变部分的旧证据有适用依据；当前格式与最终版面通过；未测成员和未决来源明确披露。未决项使对应族不能声称已验证，不阻止交付其他已验证部分。

## 排版与字体

- **最小有效印刷字号为 5pt。**这是项目的下限，不是默认正文字号；若考试规定或使用者要求更大，则采用更大的下限。优先使用更易读的字号。
- 检查正文、代码、脚注、图标签、表格、公式上下标等全部承载内容的文字。导出后的变换、缩放也计入：例如 5pt 文字以 90% 打印只有 4.5pt，不合格。转为路径或图片的文字不能靠 PDF 字体清单证明字号，需追踪生成尺寸或另行测量；无法确认则报告未核验。
- 以实际尺寸排版，记录预计打印比例；检查实际可打印边距，不依赖自动“缩小以适合”。不要为了塞满版面静默降到 5pt 以下。必要时去重、缩写已解释的重复项、换栏布局或将长示范移到复习伴随材料。
- 空间受限小抄默认直接从知识模块开始，删除占版面的顶部文档大标题、版本横幅和重复使用/导航说明；来源和长说明放伴随记录。需要标识版本/页码时使用紧凑页脚。这里删除的是文档抬头，不是各知识模块标题；解释代码缩写或模板条件等答题必需内容保留。
- 先按题型设置可辨认的大区，使用稳定编号、文字标签、不同且一致的底色/边框，模块标题大于正文且加粗；避免所有题型都用无法区分的相同标题样式。模板独立成块，默认浅黄底加可见边框和 EN/答案模板等短标签。红字可用于题型识别，但须与易错警告有明确标签/样式区别。用户指定配色优先；黑白仍可定位，不改无关内容或稳定编号。
- 每页三栏之间各画一条连续黑色竖线，共两条，沿正文栏高放在栏间空隙中；其他多栏布局同样分隔相邻栏，不强制把单栏/双栏改成三栏。建议约 0.6–0.8pt，按实际尺寸检查线条清晰且文字不接触、不穿线、不跨栏。留白不能代替用户要求的黑线。
- “重点”必须说明依据，例如老师明确强调、当前范围核心、学生常错或历史出现；颜色深浅不能暗示无证据的出题概率。遵守考试颜色限制，黑白要求下改用层级、边框、字重和浅灰底。

## 最终文件验收

1. 从最终文件读取页数、页面尺寸、字体与文字位置；确认单/双面限制及有效字号下限。检查导出字体替换、缺字和源文档一致性。
2. 渲染**最终版本的每一页**，检查裁切、跨栏碰撞、行间拥挤、代码括号/缩进、公式与图标签。测过旧版不能代替当前版。
3. 查看每页实际尺寸的彩色与灰度预览，逐项记录：顶部冗余抬头/说明已去除；知识模块标题可快速辨认；答案模板底色、边框和标签清晰；三栏两条黑线完整、无文字触线；关键词可见。保留用户/考试规则要求的例外及其依据，不能只看放大的局部截图或只核对样式代码。
4. 若有实际打印条件，由使用者按目标比例试印阅读。否则明确“数字版检查通过，实际打印未验证”。agent 做题成功不替代版面检查，渲染检查也不替代物理打印。
5. 保存简短验收记录：版本/哈希、纸张/面数、最小有效字号及测量方法、打印比例、视觉问题、所测试题、agent 反馈轮次、未决项。让读者能分辨实测值、元数据和建议值。
