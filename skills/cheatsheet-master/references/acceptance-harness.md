# 全量逐题验收 harness（仅明确请求时启用）

本文件只用于用户明确要求的全量逐题验收。普通创建、修订和最终检查默认按 [peer-review-and-layout.md](peer-review-and-layout.md) 全量分类、代表题作答，不进入下述严格模式。不要只因用户说“验收”或“最终版”自动启动全量流程。

下文中的“每题”“全量”“版本变化重新验收”和每族迁移/边界配额，只在此明确选择的严格模式生效。旧版 `scripts/audit_harness.py` 仍只检查严格全量账本，不支持代表分类或增量证据复用；不要把代表题ID冒充全量清单喂给它，也不要为迁就脚本强制重做全部题。

本文件用于该严格模式的执行控制。主 agent 调度实际工具和额外独立 agent；JSON 记录保存状态，脚本计算比例并阻止不满足条件的通过声明。它不是自动判卷模型，也不假装脚本能证明任意新题都可解。

## 1. 状态与职责

`SOURCES → INVENTORY → ORDER_MAP → DRAFT → BLIND_ATTEMPTS → REVIEW → GATES → ACCEPTED / REPAIR / INCOMPLETE`

| 状态 | 必须留下的产物 | 下一步条件 |
|---|---|---|
| SOURCES | 原卷、mock、老师范围及题序说法的文件/页码/时间戳 | 区分范围证据与题序证据 |
| INVENTORY | 全量小问ID、重复原题别名、排除理由、缺失材料；独立评分要点 | 分母在查看小抄表现前固定 |
| ORDER_MAP | 题型→主分区→页/栏/稳定条目；题序证据与用户说明 | 可以从题型先缩小检索区域 |
| DRAFT | 可用小抄、源文件、逐页渲染、候选SHA-256 | 可先交付，但标明待验收 |
| BLIND_ATTEMPTS | 至少一个额外 agent 的全量实际作答、定位过程及外部知识 | 各分片并集覆盖完整清单 |
| REVIEW | 逐答案要点核验、模板支持证据、正确性、迁移题证据 | 审查者与该题解题agent分开 |
| GATES | 脚本报告、视觉检查、遗留问题 | 所有门槛通过才是 ACCEPTED |
| REPAIR | 缺口→修改条目→新哈希→失败题与变式复测 | 内部最多两轮修复；最终全量仍需匹配最终候选 |
| INCOMPLETE | 可用草稿、已完成项、未决项、下一步 | 到轮数/资源限制时诚实交付，不降低阈值 |

把每次运行保存在工作区的一个审查目录，保留 `inventory.json`、`audit.json`、`report.json` 和实际原题/答卷/渲染的引用。中断后按状态、ID和哈希续跑，不重建已经核验的同版本证据；版本变化按最终全量要求重新验收。原始题与生成变式分开统计。

## 2. “完整作答得到小抄支持”的计算

**逐题支持率 = 100 × 小抄支持且答对的必要答案要点权重之和 ÷ 完整答案全部必要要点权重之和。**

- 默认门槛为 **≥90%（含90%），每个独立小问分别达到**；不能用全卷均值抵消低支持题。另报逐题结果、各题型结果、全量通过题数/应验题数及加权概览。
- 优先用官方细分评分点的分值作权重。只有总分没有细分时，不伪造官方分配：由审查者在看作答前，根据题干和一手资料拆分可独立核验的必要步骤/输出，默认等权并标注 `derived`。保存拆分依据；有歧义先保留未决。不同权重口径的汇总只能称“审查要点加权支持率”，不能称考试得分率。
- 要点包括方法选择、适用条件、推导/状态、代码逻辑、题目要求的说明与结论。不能只按字数、句数、代码行数、关键词覆盖或模型自报百分比计算，也不能拆出大量微小要点稀释关键缺口。
- 每个要点标注 `critical`：决定方法有效性、关键前提/分支及结论正确性的要点属于关键项。**关键项必须有小抄支持且正确**；即使总比例≥90%，关键条件来自模型记忆也不通过。完整答卷本身必须正确；比例不是容许10%答案写错。
- 支持证据必须指向最终小抄中的实际条目/模板和具体内容，解释题目输入如何代入及得到该输出。题目已给数据、模板已说明的变量替换和运算不算额外课程知识；模型补出的公式、API、判断条件、算法步骤或推理桥梁属于外部知识，相关要点不计入分子。
- 允许 **A模板＋B模板＋C模板组合作答**。按答案要点的并集计权，每点最多一次。需要新的组合方法时，小抄必须包含连接步骤或可明确追踪的推导；不能靠模型补桥梁。
- 部分支持的要点，应先按独立合理标准拆分；不事后随意给0.7等主观系数。模板引用多，不会增加分数。

例：10个等权要点，A支持6点、B支持5点，重叠3点，组合支持 `(6+5−3)/10=80%`，不达标。若组合覆盖9点且所有关键项受支持、整份答案正确，还必须通过迁移与定位检查，才算达到本框架的90%支持标准；不能写成“100%无需外部知识”。剩余10%补了什么仍需列出。

`SUPPORTED` 表示上述门槛通过，`PARTIAL` 表示存在支持但门槛未通过，`UNSUPPORTED` 表示没有有效支持，`SOURCE_UNRESOLVED` 表示题源无法确定。同时显示实际百分比和失败原因，不能只给一个标签。

## 3. 泛用性：防止只存真题答案

按“方法＋适用条件＋必需输出”定义模板族，不按年份或同样关键词胡乱合并。组合模板也要验证组合路径。每族除全量原题外，至少增加两类独立变式：

1. `transfer`：改变数据、叙事情境或表面问法，仍属于同一适用范围；需实际作答并达到同样的90%支持与正确性标准。
2. `boundary`：改变一个关键前提、边界或输出要求，要求正确调整步骤、换模板，或明确拒用原模板；正确拒用也是可核验答案。

由审查者在候选冻结后设计，解题agent不能预先看到答案。每种必要的分支/输出变式都有证据；两例只是最低门槛，不能用其跳过范围内其他已知分支。若为通过某道变式修补了模板，再追加一个未见的同类变式，防止把测试答案抄回模板。报告已验证的适用边界；有限变式不能证明“遇到所有相关题都必定可用”。

## 4. 按考试题型分区定位

先记录每份原卷/mock的题型序列及老师对**考试顺序**的原话；只说重点/范围的材料不能当作顺序证据。同卷副本、答案版、转述同一来源只算一份独立证据。适用性要说明课程版本、考试形式和年份。

- 优先按适用且明确的教师当前说明，以及相互印证的卷面顺序安排主要分区；模块内再按概念依赖/解题步骤组织。证据有冲突时保留冲突，解释选用依据，不能简单数票覆盖当前明确规定。
- **有效独立顺序证据少于2份时，必须在交付说明告诉使用者：有几份、来自哪里、小抄具体按什么顺序排列、这是观察/自选检索顺序还是教师明确规定。**例如：“目前只有1份mock能说明顺序，小抄按代码阅读→概念解释→设计→测试组织；不能据此保证正式考试同序。”老师只有1条明确说明也应诚实说只有1份证据，不降低其权威、不凭空补足两份。
- 两份以上仍不代表今年必然同序；不一致或布局偏离证据时，同样说明原因。完全无证据时采用清楚的“题型→主要答题方法”顺序，并写出具体排列，不冒称历年考试顺序。
- 建立 `题型触发词 → 主分区（页/栏） → 模板ID` 路径。每个题型有明确主分区；跨主题题从主分区提供短跳转，如“再见B区12”，允许组合查阅，避免从头扫描整张纸。共享内容用固定条目和显式引用，不重复塞满各区。
- 题型大区使用稳定、可区分的标题底色/字重/边框及文字标签。可加红字体辅助识别，但红色的“题型标识”和“陷阱警告”须用标签/边框区分，不能混用同一种视觉含义。黑白打印仍可定位。每区在其位置自带短标题，不恢复占版面的顶部长说明。
- 盲解时不给作者的题型映射；agent先从题面和成品选择主分区，再定位模板。记录首选分区、实际页/栏/条目、是否扫描全表以及组合跳转路径。审查者事后比对映射，统计首次分区命中数/题数、全表扫描次数与失败题。需要扫全表或频繁误入区的题必须修复导航；不以模型记住答案冒充检索成功。不伪造学生用时。

## 5. 机器可读记录与运行

`audit.json` 使用UTF-8；完整可执行的合成结构见 [test_audit_harness.py](../scripts/test_audit_harness.py) 的 `fixture()`，它仅测试程序，不是课程验收数据。必需字段如下：

| 层级 | 字段与含义 |
|---|---|
| 根 | `schema_version: 1`, `candidate_sha256`, `author_id`, `expected_ids`（来自全量清单）, `entries`, `questions`, `variants`, `layout` |
| entries | 以稳定模板/导航条目ID为键，每项含 `region`；跨区入口另有 `links`（成品上明确指向的条目ID）；真实内容来自候选文件，证据须能定位 |
| 每个question/variant | `id`, `family`, `source`（原题定位/变式题干引用）, `source_resolved`, `rubric_basis: official/derived`, `rubric_locator`, `expected_region`, `units`, `attempt`；变式另有 `variant_kind: transfer/boundary` |
| 评分units | 每项 `id`, `weight`（正有限数）, `critical`（布尔）；为完整答案分母，审查者独立预先确定 |
| attempt | `candidate_sha256`, `agent_id`, `answer`（完整作答或实际答卷定位）, `correct`, `reviewer_id`, `review_evidence`, `first_region`, `whole_sheet_search`, `lookup_path`（实际查阅条目ID顺序，含导航入口）, `navigation_evidence`（识题与跳转过程）, `units` |
| attempt.units | 与评分要点ID完全对应；每项 `id`, `correct`, `supported_by`（一个或多个模板ID）, `support_evidence`（内容及代入/组合推导）, `external_knowledge`（无则空字符串） |
| layout | `regions`（每区 `id/title/question_types`）, `chosen_sequence`（分区ID顺序）, `rationale`, `order_sources`, `disclosure`（给使用者的实际说明）, `visual_verified`, `visual_evidence`（最终逐页渲染检查引用） |
| order_sources | 每项 `id`, `independence_key`（重复同源使用同键）, `kind: paper/mock/teacher`, `locator`, `applicable`, `sequence`（映射后的分区ID序列）；完整原始题序保存在来源记录 |

盲解agent只拿候选、小抄本身索引及分配原题；不能拿 `expected_region`、评分答案、作者组合路线或他人的作答。审查者之后合并盲解结果、事先确定的评分要点和题型地图，形成完整账本。保存原始作答，不将审查者补好的答案冒称盲解结果。

```text
python -X utf8 scripts/audit_harness.py audit.json --sheet candidate.pdf --output report.json
python -X utf8 -m unittest discover -s scripts -p test_audit_harness.py
```

退出码：0=账本声明的证据满足门槛；1=失败/未完成；2=输入结构或读取错误。脚本校验实际候选哈希、ID集合、独立角色标识、要点权重、模板并集、逐题90%、关键项、迁移/边界记录、首分区及跨区链接路径、题序证据计数与披露、视觉审查记录是否齐全。它不执行LLM、不会生成或猜测评分点。全量源清单是否完整、分母是否预先固定、agent是否真正独立、模板组合桥梁是否有效、变式是否真正未见且有意义、原图是否清楚，必须由主agent核查。不同题干引用不能自行证明泛用性；有字符串记录也不等于完成真实审查。

报告保留每题分数及问题、来源未决、全量分母与遗漏、题型定位和变式结果。来源未决不计成已答题，加权概览只覆盖有分母的已解析题，必须同时显示未决数量；不能以这个较高概览替代全量通过率。总体通过率以 `expected_ids` 为分母，缺题仍占分母；重复/额外记录使验收失败且不增加统计分子。`family` 统计只覆盖已经返回的预期唯一题，字段明确标作 `pass_percent_of_returned_questions`；存在缺题时不能将其称为该题型全量通过率。生成变式不混入正式题分母。

交付时附：题型排列及依据（证据不足2份的明确说明）、全题验收范围、逐题与题型支持率、低于90%/关键缺口/迁移失败清单、定位失败及最终版面核验。支持率不是学生掌握率，也不是预期考试分数。
