# 用 @ 压缩重复代码

当多个条目反复出现相同代码时，可以定义一次公共片段，用 `@名称` 在原位置引用。目的是节省版面并保留完整代码；若定义和查找成本反而更高，就保留展开形式。

## 约定

- `@H1`、`@SWAP(A,i,j)` 等是**小抄里的展开标记**。首次使用处写明“看到 @，把对应代码原地展开”，不能让读者自行猜测。
- 每个标记必须有唯一、完整、可定位的定义，放在允许携带的小抄上，优先靠近第一次使用或同一面。不能只把定义放进另一本复习指南。
- 默认只提取真正相同的代码。变量名或参数不同则明确写出参数及替换规则；实际参数限于兼容类型的简单变量/下标，不把有副作用的表达式代入多次。记录会修改哪些变量、临时变量需求与适用前提。
- 保留执行顺序、条件、循环边界、返回位置、括号、作用域和变量生命周期。共享定义中的临时变量不能遮蔽或破坏调用位置的已有值；有冲突时显式重命名或改回展开代码。
- 不同算法只是“看起来相似”时不能直接合并。例如线性探测、二次探测的推进式不同，Map 与 Set、带删除标记与不带删除标记的分支也可能不同；差异要原地可见。
- 优先单层引用，避免嵌套；若确需嵌套，依赖必须无环，展开顺序明确，且读者能在当前小抄内完成全部展开。
- 考试要求完整代码/伪代码时，把片段展开后再写。只有题目允许并已定义相应辅助操作时，才能保留相应调用；不能把未解释的 `@H1` 当作 Java、Python 或标准伪代码语法。
- 用户觉得跳转难用时，可将相关条目局部展开；不强迫整页使用相同压缩程度。

## 原创例子：公共交换片段

定义一次，说明 `A` 为可修改数组，`i`、`j` 为合法下标，`tmp` 为该处专用的临时变量：

```text
@SWAP(A, i, j) :=
    tmp <- A[i]
    A[i] <- A[j]
    A[j] <- tmp
```

条目中可写：

```text
if A[mid] = 0 then
    @SWAP(A, low, mid)
    low <- low + 1
    mid <- mid + 1
else if A[mid] = 2 then
    @SWAP(A, mid, high)
    high <- high - 1
```

第一处展开为 `tmp <- A[low]`、`A[low] <- A[mid]`、`A[mid] <- tmp`；第二处把参数换成 `mid, high`。指针更新属于各自分支，**不能跟着交换片段一起合并**：处理 2 的分支不增加 mid。这里只展示两个分支用于说明压缩，不是完整排序算法。

这个例子演示展开语义；是否省空间取决于实际重复次数、定义长度和布局，不能默认加 @ 就更紧凑。

## 验收

保存展开前代码作为核对依据。展开每处 @ 后，核对完整代码与原版本是否一致（仅允许约定的参数改名及无关空白变化），再针对边界、分支差异和临时变量冲突做必要检查。任何语义性改动都应作为单独修改验证，不能藏在“压缩”中。

让独立解题 agent 只用候选小抄找到定义、展开引用并完成相关题目，报告是否需要作者额外解释；若定义找不到、参数不明、展开改变逻辑或阅读成本过高，则补全、移动定义或局部展开。最终仍须满足页数和有效字号下限。
